# 第三阶段资产负债规格

## 目标与边界

本阶段把既有离线预算演示升级为可管理现金、储蓄卡、电子钱包、信用卡、借贷和投资六类账户的四页小程序。仍只支持人民币、整数分和 `schemaVersion=1`；不新增网络、云同步、行情、汇率、收益预测、投资建议、固定计划、退款界面、预算修改、图表或 AI。

页面只能调用 `src/application/app-core.js`。账户余额、负债、预算影响、投资成本和流水必须由既有 `src/domain/` 函数产生；页面不得直接改账本余额，也不得复制预算公式。每次成功操作立即保存完整版本化 JSON，失败展示中文错误且不产生半笔交易。

## 账户决策表

| 类型 | 账本性质 | 余额含义 | 可用于普通支出 | 可接收收入 | 专项操作 |
| --- | --- | --- | --- | --- | --- |
| 现金 | 资产 | 可用现金 | 是 | 是 | 转账、还款、借贷收款、还本、付息、投资买卖 |
| 储蓄卡 | 资产 | 可用存款 | 是 | 是 | 同上 |
| 电子钱包 | 资产 | 可用余额 | 是 | 是 | 同上 |
| 信用卡 | 负债 | 当前欠款 | 是，消费增加负债 | 否 | 资产账户还款 |
| 借贷 | 负债 | 待还本金 | 否 | 否 | 借款、归还本金、关联利息 |
| 投资 | 资产 | 手填现值 | 否 | 可记录收入，但买卖走专项入口 | 买入、卖出、手工估值；另存投入成本 |

## 交易与预算决策表

| 操作 | 资产变化 | 负债变化 | 可控预算 |
| --- | --- | --- | --- |
| 收入 | 收款账户增加 | 无 | 不增加也不扣减 |
| 现金类可控支出 | 付款账户减少 | 无 | 扣减 |
| 信用卡可控支出 | 无 | 信用卡欠款增加 | 扣减 |
| 固定支出 | 付款账户减少 | 无 | 不扣减 |
| 资产账户互转 | 一减一增 | 无 | 不扣减 |
| 信用卡还款 | 付款资产减少 | 信用卡欠款减少 | 不扣减 |
| 借款 | 收款资产增加 | 贷款本金增加 | 不扣减 |
| 归还本金 | 付款资产减少 | 贷款本金减少 | 不扣减 |
| 支付利息 | 付款资产减少 | 本金不变 | 固定支出，不扣减 |
| 投资买入/卖出 | 现金类与投资资产转换 | 无 | 不扣减 |
| 手工估值 | 投资现值改为输入值 | 无 | 不扣减 |

## 页面契约

- 首页保留今日额度、预支和周期结算，增加“资产中心”入口。
- 设置页首次启动仍设置预算和初始现金类账户；初始化后复用为资产中心，显示四项汇总、六类账户、新增账户和债务/投资专项操作。
- “记一笔”顶部固定提供“支出 / 收入 / 转账”。收入不能选择信用卡或借贷；转出与转入不能相同；信用卡支出仍使用支出入口。
- 最近账单升级为最近流水，显示类型、日期、金额、账户方向与是否计入预算；旧支出交易继续显示。

## 兼容与恢复

第二阶段 `schemaVersion=1` JSON 直接加载，不升级 schema、不删除旧账户或旧交易。新增账户仍使用版本一已有字段；投资投入成本使用既有 `costBasisCents`。序列化往返后账户、余额、交易、预算周期和关联账户必须保持一致；损坏存储继续返回原始数据和明确错误。

## 固定验收样例

初始：现金 1000、储蓄卡 2000、钱包 300、信用卡欠款 500、贷款欠款 3000、投资现值 1000/成本 800。依次执行收入 1000、现金转卡 300、信用卡可控支出 120、储蓄卡还卡 200、借款 1000、还本 400、付息 50、投资买入 500、手工估值 1550。

最终：总资产 5700、总负债 4020、净资产 1680、现金 1750、储蓄卡 2100、信用卡 420、贷款 3600、投资 1550；可控预算只扣 120。
