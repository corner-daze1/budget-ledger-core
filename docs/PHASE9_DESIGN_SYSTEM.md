# 用度 · 阶段九设计规范（产品评审样板）

本规范描述首页高保真候选样板：让用户一眼看懂今天能花多少、额度如何积累，并看到最近账单。
业务算法、路由与其他三页本阶段不改。执行者交付候选样板，不得自称已获产品视觉认可。

## 1. 品牌气质与禁区

**气质**

- 暖米白、墨黑、少量青柚；预支用克制的陶土红。
- 像随身小账本，不是银行 App。

**禁区**

- 黑色金融主卡、YONGDU/TODAY 式英文装饰眉题。
- 常驻空计划卡、首页「资产中心」大按钮、底部导航、新路由。
- 把预算刻度伪装成「月预算百分比」。
- 外部图片、字体、图标库、组件库、网络能力。

## 2. 颜色

| 角色 | 值 | 用途 |
|------|-----|------|
| 页面背景 | `#F7F3EA` | 暖米底 |
| 卡片 | `#FFFDFA` | 主内容卡 |
| 正文 | `#22231F` | 主文案、主按钮底 |
| 次文 | `#756B63` | 说明、次级标签 |
| 品牌青柚 | `#D8F15A` | 刻度强调、点缀 |
| 正常状态文 | `#5F7055` | 正常积攒说明 |
| 预支文 | `#A94D3B` | 预支说明 |
| 描边 | `#E8E1D6` | 卡片边 |
| 主按钮字 | `#FFFDFA` | 深色主按钮上的浅色字 |

对比度目标：普通文字 ≥ 4.5:1（`#22231F`/`#756B63` 于 `#F7F3EA`；主按钮浅字于 `#22231F`）。

## 3. 字体与点击

- 最小正文 **24rpx**；主金额可更大（≥48rpx）。
- 主要点击区域高度 ≥ **88rpx**。
- 320px 允许纵向滚动；长金额 `overflow-wrap: anywhere`；操作不被安全区遮挡。

## 4. 首页结构

1. **页头**：自然中文标题与「管理」同一行；320px 不得折成上下两行或把「管理」拉满宽。
2. **预算刻度主卡**：突出「今日可自由花」与大金额；固定日额度作为明确刻度。
   - 正常：显示比日基准多出的额度（积攒感），精确金额以文字为准。
   - 预支：显示「已预支未来额度…」与「预计…恢复至每日…」。
   - 刻度饱和显示，不暗示虚假月预算百分比。
3. **＋记一笔**：唯一强 CTA，位于预算卡之后、最近账单之前。
4. **最近账单**：最多 5 笔真实分类/日期/账户/金额；分类由 `categoryLevel1`/`categoryLevel2` 有效值用「 · 」拼接，过滤空值与字面 null/undefined，全缺时「未分类」；金额与主体保持横向；空状态「还没有账单，记下第一笔」；「全部」进账单页且不得 width:100%。
5. **事件提醒**：逾期横幅、待处理区各自独立；通用「计划与提醒」卡仅由 executionResults / reminders / dueToday / executionMessage 触发；禁止隐藏注释或源码锚点冒充空计划契约。

## 5. 六种状态

| 状态 | 表现 |
|------|------|
| 正常 | 浅色主卡 + 日额度刻度 + 积攒说明 |
| 预支 | 陶土红说明 + 恢复日/每日额 |
| 待结算 | 结算卡替换主卡；须选择结余/超支 |
| 计划提醒 | 有提醒/到期才出现计划区 |
| 待处理 | 补金额 + 重试入账 |
| 错误 | 顶部错误条 |
| 账单空 | 「还没有账单，记下第一笔」 |

## 6. 数据契约

- 绑定真实 `model.todayFree`、`fullSingleDayQuota`、`prepaid`、`earliestRecoveryDate`。
- `home.js` 经现有 `core.listRecentBills` 取账单，截断最多 5 笔，经 `formatBillCategory` 组装展示分类，不造假数据。
- `hasPlanEvents` 只判断通用计划摘要四类字段；逾期与待处理不打开通用卡。
- 「管理」「全部」可点高度 ≥ 88rpx。
- 不改 `src/domain`、`src/application`、`miniprogram/lib` 与其他三页。

## 7. 验收

- 自动化：契约测试（绑定、listRecentBills、状态、可达、对比度、字号、禁区）。
- 人工：Stable 双机型正常/预支真实截图；风格由产品方确认。
