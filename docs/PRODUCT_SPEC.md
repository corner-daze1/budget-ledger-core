# 记账小程序首版产品规格

## 界限

当前参赛版是离线原生微信小程序，支持人民币与整数分；领域内核不依赖微信运行时、浏览器、网络、文件系统或密钥。产品已包含动态累计预算、六类账户、计划与小程序内提醒、三张分析图、JSON 完整备份与恢复预检、CSV 账单导出。首版仍不包含 AI分析、云同步、行情、汇率、会员和后台定时通知。

## 预算规则

| 决策 | 规则 |
|---|---|
| 可控预算 | 月度可控预算不含固定支出；账单有两级分类，但不设分类预算。收入只增加资产，不自动增加预算。 |
| 金额 | 所有金额都是整数分；累计释放使用累计取整，周期最后一天累计释放恰好等于总预算。 |
| 本期实际预算 | 基础预算加有符号结转。若负结转超过基础预算，本期实际预算为0，未抵完的负数继续作为待偿预算债务。 |
| 结转 | 正结余可带入下期或进入奖励余额；超支可带入下期或使用奖励余额抵扣。 |
| 释放 | 按周期实际天数释放，任意相邻日的分钱结果最多相差1分。今日可自由花=max(0，累计释放-计入预算净支出)。 |
| 预支 | 当计入预算净支出超过累计释放时，今日可自由花为0，并返回已预支金额和恢复到完整单日额度的最早日期。 |
| 奖励 | 奖励余额可全额或部分抵扣；抵扣部分不占本期预算，余额不得为负。 |

## 周期与起始日

周期起始日只能是1—31。目标月份没有该日时取月末，例如31日规则在2月从2月最后一天开始。修改起始日不移动历史账：旧周期自然结束，随后生成一次性过渡周期，再进入新起始日周期。过渡预算按“默认月预算×过渡天数÷该月实际天数”取整；当前预算和未来默认模板分开。

预算修改范围固定为“仅本周期”（`only_current`）、“本期及以后”（`current_and_future`）和“下期及以后”（`next_and_future`）。范围修改只改变适用模板，不回写已关闭周期。

## 资金与流水

账户类型包括现金、储蓄卡、电子钱包、信用卡、借贷和投资账户。收入增加资产；可控支出减少资产并增加本期预算支出；固定支出减少资产但不扣预算；账户互转不改变净资产。信用卡消费增加负债并按支出性质扣预算，还款只是资产转负债，不重复算支出。借款同时增加现金和负债；还本金同时减少现金和负债；利息作为固定支出。投资买卖只做资产形态转换，成本和现值由用户手填，不做行情、汇率或预测。

普通退款在原周期仍开放时恢复该周期预算；原周期已关闭时进入奖励余额。奖励支付退款只退回奖励余额。固定金额计划可以指定账户自动入账并携带来源、可撤销；金额未定或余额不足只生成待确认项，不改账户余额。

总资产、总负债、净资产、预算和奖励余额分别计算，任何一项不得冒充另一项。

## 数据恢复与导出

数据使用版本化 JSON schema。备份包含账户、交易、预算周期、奖励余额、计划、待确认项和关联关系。迁移只接受已知版本；损坏数据返回明确错误和原始文本，不静默清空。序列化往返必须保持金额、日期、关联交易和账户余额。JSON 经预检和双重确认后原子恢复；CSV 账单导出使用固定列并正确转义逗号、引号和换行，不能用于恢复。

## 小程序体验

当前实现：账本页展示动态累计预算、固定日基准、积攒或预支恢复信息和最多五笔近期账单；只有真实计划事件、逾期或待处理存在时才出现相应提醒。底部视觉导航为“账本｜记一笔｜我的”，中央“记一笔”是动作而非 Tab；完整账单与分析从账本页“全部”进入。记账页统一处理支出、收入和转账；账单分析提供每日净支出、一级分类占比、最近六个真实周期趋势三张分析图，并支持可控支出与全部支出两种口径。

首页已采用暖灰、松绿和“预算刻度带”的第二版视觉，详细规范见 `docs/PHASE10_TDESIGN_UI_SPEC.md`。实现与静态视觉契约测试已经通过，但 Stable/automator 的自动截图运行仍阻塞于 `App.captureScreenshot` 无匹配回复，不能称为自动取证通过；视觉细节也仍待产品方审阅。确认前不把内容重绘铺到我的、记账和账单分析三页。

首次设置表单直接展开。初始化后的设置页使用四个互斥折叠分区：“预算与周期、计划提醒、资产账户、数据与隐私”；默认展开预算分区，重复点击可全部收起。分区标题显示真实摘要，错误和成功反馈出现在所属分区内。计划提醒只在小程序启动或回到前台时检查，不冒充后台定时通知。

## 首版排除项

首版不提供 AI分析、云同步、行情、汇率、会员或后台定时通知，也不承诺账号找回、自动上传或加密云备份。JSON 与 CSV 都是用户主动导出的本地明文文件。
