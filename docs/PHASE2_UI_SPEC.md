# 第二阶段 UI 规格

## 目标与边界

本阶段只交付“用度（暂定）”的原生微信小程序核心闭环：设置、首页、记一笔、最近账单。页面不复制预算公式、不直接改余额；页面输入统一交给 `src/application/app-core.js`，由既有 `src/domain/` 负责金额与周期事实。

不做 AI、云同步、网络请求、行情、汇率、预测、语音、图表、真实提醒、固定计划界面、完整资产管理、收入和转账。首版只支持 CNY，分类使用内置两级分类。

## 页面契约

| 页面 | 用户可见内容 | 应用层入口 |
| --- | --- | --- |
| 设置 | 月度可控预算、周期起始日、多个现金/储蓄卡/电子钱包账户及余额；固定支出提示 | `initializeState`、`savePersisted` |
| 首页 | 今日可自由花、已预支未来额度、完整单日额度、恢复日期、记一笔/账单/设置入口 | `getHomeModel` |
| 记一笔 | 金额、日期、账户、一级/二级分类、备注、计入可控预算开关 | `recordEntry`、`findPreviousSimilar` |
| 最近账单 | 日期倒序、同日按录入顺序倒序；可控/固定、分类、账户、日期、金额和备注 | `listRecentBills` |

## 业务行为

- 首次启动无状态时进入设置；设置成功创建当前预算周期并写入版本化 JSON 本地存储。
- 可控支出使用既有领域函数扣预算；关闭“计入可控预算”时记录固定支出，不扣月度可控预算。
- 同类提示先按二级分类精确匹配；无精确结果时回退一级分类；只显示金额和日期，找不到时显示“暂无记录”。
- 首页“今日可自由花”为真实预算快照；预支时显示已预支金额及恢复完整单日额度的最早日期。
- 金额在应用层和领域层使用整数分；页面只负责元的输入和展示，不进行浮点累计。
- 本地存储损坏时保留原始文本并显示错误，不清空、不生成替代账本。

## 运行与交付证据

`npm run build:mini` 从领域层和应用层生成小程序本地 CommonJS 包；`npm run check:mini` 校验页面、生成物、源代码边界和私有开发者配置忽略规则。微信开发者工具截图放在 `artifacts/phase2/`，真实 AppID 不允许猜测或伪造；若工具仅因缺少 AppID 报运行时错误，必须在 `BLOCKED.md` 记录，不能声称控制台零错误。
